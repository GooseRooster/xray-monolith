## Hot-zone / deep-read commits

### a390f9b1 - xrPhysics: optional clamp on actor camera collision box at high FOV to fix ultrawide doorway snag
Adds `g_clamp_actor_camera_collision` (default `FALSE`). When enabled, clamps
the world-collision box's `bs.x`/`bs.y` (built from FOV-driven viewport-near
geometry) to FOV-75-equivalent values, fixing a doorway/corridor snag at high
FOV/ultrawide where the box gets wide enough to catch on doorframes and stall
actor movement for ~1s. The NPC-vs-character collision cylinder is untouched
(still uses unmodified `box_size.x`), so this is purely the world-collision
box. Insertion point (`ActorCameraCollision.cpp`, `set_camera_collision()`)
is additive and self-contained.
Gotchas: none found - default-off, so no behavior change until a player
opts in. Verdict: unchanged (take).

### e0f86304 - first person death improvements (head collision scale, cvar)
On the alive→dead transition (edge-detected via a function-static bool,
correctly re-armed every frame the actor is alive so it isn't a one-shot
per process), scales the `bip01_head` physics element by
`first_person_death_head_scale` (new cvar, default `3.0`, range 1-10) to
stop the death camera clipping into the ground. Backing implementation adds
a general-purpose `CPHElement::SetScale()` / `CPHShell::SetScale()` (new
virtual, plumbed through `PhysicsShell.h`) that rescales all box/sphere/
cylinder geoms and the element's local mass center. Checked the scaling
math for the classic "scale twice" bug (dividing by `prev_scale` before
multiplying by the new scale for sizes/radii/mass-center, vs. multiplying
fixed unscaled `local_center()` values directly) - it's internally
consistent and idempotent across repeated calls with different scale
values, not just the single 1.0→3.0 case this commit actually exercises.
No ragdoll-joint-anchor adjustment accompanies the geom rescale, so a
3x head on a body whose neck joint anchor didn't move could look like a
slight snap/pop at the moment of death - minor, but part of why this
gets a playtest flag rather than a clean pass.
Confirmed the insertion point in our tree (`ActorCameras.cpp`, the
`firstPersonDeath && !g_Alive() && m_FPCam` block, lines ~805-850) matches
upstream's pre-image exactly, and doesn't overlap Old World's own
fp-body chest-clearance raycasting added just above it (that code is
`g_Alive()`-gated, so it never runs during the death-cam path this commit
touches) - low integration risk despite `ActorCameras.cpp` being a heavily
customized file.
Note: `console_commands.cpp` hunk in the upstream diff also strips a BOM
and retabs a few nearby lines to spaces - cosmetic churn, may add a little
merge noise but nothing behavioral.
Gotchas: → `playtest` (head-scale-on-death is not gated behind an
off-by-default toggle - `firstPersonDeath` is already default `TRUE` in
this fork, so this is a default visual/physics change to the death camera
the moment it lands). Verdict: unchanged (take), flagged for a playtest
pass after applying.
